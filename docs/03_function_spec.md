# 03. 기능명세서

## 1. Agent 기능

| ID | 기능명 | 담당 컴포넌트 | 입력 | 주요 처리 | 출력/완료 조건 |
|---|---|---|---|---|---|
| AG-01 | 문의 분류 | Supervisor | 사용자 메시지, 상담 State | 문의 유형 및 후속 발화 여부 판단 | `worker1~4` 또는 `fallback` 라우팅 |
| AG-02 | 가까운 지점 조회 | Worker1 | 위치/주소/등록 주소 | 검색 기준점 결정 → Redis GEO 조회 | 거리순 지점 정보 |
| AG-03 | 재고 조회 | Worker2 | 지점·제품·카테고리 | 사용자 표현 추출 → 지점/상품 재고 Tool 조회 | 상품명·수량·지점 정보 |
| AG-04 | 주문·배송 조회 | Worker3 | 사용자·주문 관련 질문 | 주문/배송 Tool 선택 및 조회 | 주문 내역, 배송 상태, 예상일 |
| AG-05 | 배송지 변경 | Worker3 | 주문, 변경 주소 | 대상 주문 확인 → 변경 요청 생성 | `ADDRESS_CHANGE / PENDING` 요청 |
| AG-06 | 교환 처리 | Worker4 | 주문, 사유, 방법 | 주문 확인 → 정책 검색 → 교환 방식 확인 → 요청 생성 | `EXCHANGE / PENDING` 요청 |
| AG-07 | 환불 처리 | Worker4 | 주문, 사유, 방법 | 주문 확인 → 정책 검색 → 환불 흐름 진행 | `REFUND / PENDING` 요청 |
| AG-08 | 응답 검증 | Validator | Worker 초안, `tool_results` | 숫자·날짜·주소·지점 등 사실 대조 | 통과 → Respond / 실패 → 재작성 |
| AG-09 | 범위 밖 처리 | Fallback | 지원 범위 외 문의 | 문의 저장 및 안내 문구 생성 | `inquiries` 저장 + 상담원 연결 안내 |
| AG-10 | 최종 응답 | Respond | 검증 완료 답변 | 검증 완료 답변을 대화 State에 반영 | 사용자 응답 반환 |

## 3. 지점·재고 기능 규칙

### 3.1 지점 조회

- 사용 가능한 검색 기준:
  - 브라우저 현재 위치
  - 사용자가 입력한 주소
  - DB에 저장된 사용자 등록 주소
- 기본 검색 반경: **50 km**
- 결과가 없을 경우: **200 km**로 1회 확장
- Redis GEO Key: `stores:geo`
- 검색 기준 정보는 Worker1·Worker2가 공유한다.

### 3.2 재고 조회

- 지점명이 명시되면 해당 지점 재고를 우선 조회한다.
- 제품명이 명시되면 해당 제품으로 범위를 제한한다.
- 지점이 명확하지 않은 경우 검색 기준 위치를 확인한다.
- 결과는 지점명, 제품코드, 제품명, 카테고리, 수량, 가격 정보로 UI 카드에 전달할 수 있다.

## 4. 주문·배송 기능 규칙

- 주문 내역은 로그인 사용자(`user_id`) 기준으로 조회한다.
- 배송 상태는 `PREPARING`, `SHIPPED`, `IN_TRANSIT`, `DELIVERED` 중 하나이다.
- 배송 상태 변경 이력은 `delivery` 테이블에 이벤트 단위로 저장한다.
- 배송지 변경은 주문 정보를 직접 즉시 수정하지 않고 `requests` 테이블에 `PENDING`으로 접수한다.
- 관리자 승인/거절 API에서 요청 상태를 변경한다.
- 처리 결과는 사용자 알림 API에서 조회할 수 있다.

## 5. 교환·환불 기능 규칙

- 사용자의 주문을 기준으로 대상 상품을 확인한다.
- 배송 완료 여부 및 수령일 등 처리 가능 조건을 확인한다.
- 분쟁해결기준은 `dispute_docs`에서 pgvector 검색을 통해 참고한다.
- 교환/환불 방법은 `STORE_VISIT` 또는 `PICKUP`을 사용할 수 있다.
- 최종 요청은 `requests`에 `EXCHANGE` 또는 `REFUND` 유형으로 저장한다.
- 같은 내용의 중복 요청이 생성되지 않도록 확인한다.

## 6. Validator 규칙

- Worker가 만든 자연어 답변의 사실 정보는 `tool_results`와 비교한다.
- 주요 검증 대상:
  - 숫자
  - 날짜
  - 지점명
  - 주소
  - 주문/상품 관련 핵심 값
- 검증 성공: `respond`
- 검증 실패: 동일 Worker 재작성
- 기본 최대 재작성 횟수: **2회**
- 재시도 초과: `fallback`
